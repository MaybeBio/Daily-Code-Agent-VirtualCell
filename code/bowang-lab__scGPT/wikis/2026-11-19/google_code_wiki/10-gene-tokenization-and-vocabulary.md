## Gene Tokenization and Vocabulary
[`scGPT`](https://github.com/bowang-lab/scgpt/README.md#L1) manages gene vocabularies for single-cell gene expression data, which involves creating, loading, and applying these vocabularies to convert gene expression measurements into tokenized representations suitable for transformer models. This process ensures that gene expression data can be uniformly processed and fed into models, regardless of variations in the input data. The system dynamically adapts to changes in the [`torchtext`](https://github.com/bowang-lab/scgpt/docs/environment.yml#L19) [`Vocab`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/vocab_compat.py#L251) API, maintaining compatibility across different [`torchtext`](https://github.com/bowang-lab/scgpt/docs/environment.yml#L19) versions.

The core of this system is defined in the [`/bowang-lab/scgpt/scgpt/tokenizer`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer) directory, which provides functionalities for vocabulary management and data processing. The [`GeneVocab`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/gene_tokenizer.py#L24) class, found in [`/bowang-lab/scgpt/scgpt/tokenizer/gene_tokenizer.py`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/gene_tokenizer.py), is central to this. It handles the initialization of vocabularies from various sources, including lists of gene names or existing vocabulary objects. [`GeneVocab`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/gene_tokenizer.py#L24) also supports loading and saving vocabularies to files, such as [`.pkl`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/gene_tokenizer.py#L120) or [`.json`](https://github.com/bowang-lab/scgpt/scgpt/utils/util.py#L223) formats, for persistence and reuse. It incorporates mechanisms for managing special tokens (e.g., for padding or classification) and for setting a default token. For instance, the [`pad_token`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/gene_tokenizer.py#L201) property ensures proper padding within batches. A [`get_default_gene_vocab`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/gene_tokenizer.py#L242) function is available to retrieve or construct a standard gene vocabulary, potentially fetching gene symbols from external sources like [`genenames.org`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/gene_tokenizer.py#L274).

Beyond vocabulary creation, the system includes utilities for tokenizing and padding gene expression data. Functions like [`tokenize_batch`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/gene_tokenizer.py#L292) convert numerical gene expression values and identifiers into tokenized representations, often including special tokens like a [`cls_id`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/gene_tokenizer.py#L298) (classification token). [`pad_batch`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/gene_tokenizer.py#L355) then takes these tokenized batches and pads them to a uniform length ([`max_len`](https://github.com/bowang-lab/scgpt/scgpt/trainer.py#L525)) using a specified [`pad_token`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/gene_tokenizer.py#L201) and [`pad_value`](https://github.com/bowang-lab/scgpt/scgpt/data_collator.py#L39), ensuring that all input sequences to the model have consistent dimensions. If a batch item exceeds the maximum length, genes are sampled to fit the constraint while preserving critical tokens. The [`tokenize_and_pad_batch`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/gene_tokenizer.py#L442) utility combines these steps for a streamlined workflow. Additionally, [`random_mask_value`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/gene_tokenizer.py#L485) facilitates tasks such as Masked Language Modeling by randomly masking a proportion of gene expression values in a batch, excluding padding values.

A crucial aspect of [`scGPT`](https://github.com/bowang-lab/scgpt/README.md#L1)'s gene tokenization system is its adaptability to [`torchtext`](https://github.com/bowang-lab/scgpt/docs/environment.yml#L19) [`Vocab`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/vocab_compat.py#L251) API changes, as handled by [`/bowang-lab/scgpt/scgpt/tokenizer/vocab_compat.py`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/vocab_compat.py). This module dynamically probes whether [`torchtext.vocab.Vocab`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/vocab_compat.py#L14) can be subclassed. If it cannot (a common issue with newer [`torchtext`](https://github.com/bowang-lab/scgpt/docs/environment.yml#L19) versions), the system gracefully falls back to a pure-Python [`BuiltinVocab`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/vocab_compat.py#L81) implementation. This [`BuiltinVocab`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/vocab_compat.py#L81) mirrors the public API of [`torchtext.vocab.Vocab`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/vocab_compat.py#L14), providing a consistent interface for [`GeneVocab`](https://github.com/bowang-lab/scgpt/scgpt/tokenizer/gene_tokenizer.py#L24) regardless of the underlying [`torchtext`](https://github.com/bowang-lab/scgpt/docs/environment.yml#L19) version. This design ensures that [`scGPT`](https://github.com/bowang-lab/scgpt/README.md#L1) remains robust against external library updates while maintaining its core functionality for gene tokenization.
