### Biomni Agent (A1) Architecture and Workflow
The [`A1`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L56) agent, defined in [`/snap-stanford/biomni/biomni/agent/a1.py`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py), serves as the primary AI agent within the [`biomni`](https://github.com/snap-stanford/biomni/README.md#L25) framework, orchestrating complex biomedical research tasks. Its architecture facilitates autonomous problem-solving through an interactive coding environment, dynamic tool and resource management, and comprehensive conversational logging.

The agent's workflow is managed by a [`StateGraph`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L15), which defines a state machine to control the sequence of operations. This graph typically includes a [`generate`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L1381) node, responsible for invoking the underlying Large Language Model (LLM) to produce an action, and an [`execute`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L1471) node, which runs generated code in Python, R, or Bash environments. This design allows the [`A1`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L56) agent to iteratively plan, execute, and observe results, mimicking a human researcher's approach. Optional self-criticism capabilities can be integrated into this workflow, where an [`execute_self_critic`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L1579) node provides feedback to the LLM based on execution history, prompting for refinement or correction.

A core aspect of the [`A1`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L56) agent's functionality is its dynamic management of tools and resources. It can dynamically add new callable Python functions as tools, automatically generating API schemas and registering them for LLM use. Furthermore, it supports the integration of tools from external Multi-Component Protocol (MCP) servers, enabling the agent to extend its capabilities beyond its local environment. Beyond tools, the agent manages custom datasets and software libraries, incorporating them into the LLM's context. When [`use_tool_retriever`](https://github.com/snap-stanford/biomni/biomni/config.py#L40) is enabled, the agent leverages a [`ToolRetriever`](https://github.com/snap-stanford/biomni/biomni/model/retriever.py#L8) to intelligently select relevant tools, data, libraries, and know-how documents based on the user's prompt, dynamically updating the system prompt provided to the LLM. This ensures that the LLM operates with a highly contextualized and relevant set of resources. For more information on resource management and retrieval, refer to [Dynamic Resource Management and Retrieval](#project-overview-and-core-components-dynamic-resource-management-and-retrieval).

The [`A1`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L56) agent integrates various components to support its operations. It interacts with LLMs for reasoning and code generation. For details on LLM integration, see [LLM Integration and Configuration](#project-overview-and-core-components-llm-integration-and-configuration). Code execution, a critical part of its workflow, involves running Python, R, or Bash scripts generated by the LLM, capturing outputs, and handling plots. This aspect is further detailed in [Code Generation and Execution](#project-overview-and-core-components-code-generation-and-execution).

Conversation history logging is another integral feature. The agent maintains a detailed log of interactions, including user prompts, LLM responses, code executions, and observations. This log can be exported as a PDF report, providing a comprehensive record for review, debugging, and reproducibility. This ensures transparency and traceability of the agent's autonomous research process. The [`A1`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L56) agent also manages resource loading based on [`commercial_mode`](https://github.com/snap-stanford/biomni/biomni/config.py#L43), accommodating different licensing requirements for datasets in academic versus commercial settings.
