### Tool Descriptions and Domains
The [`biomni`](https://github.com/snap-stanford/biomni/README.md#L25) project employs a structured metadata system to define and categorize its extensive collection of biological and medical tools. This system, primarily located under the [`/snap-stanford/biomni/biomni/tool/tool_description`](https://github.com/snap-stanford/biomni/biomni/tool/tool_description) directory, allows for programmatic discovery, invocation, and validation of tool functionalities. Tool descriptions are organized by scientific discipline, with dedicated Python files for areas such as biochemistry ([`/snap-stanford/biomni/biomni/tool/tool_description/biochemistry.py`](https://github.com/snap-stanford/biomni/biomni/tool/tool_description/biochemistry.py)), bioengineering ([`/snap-stanford/biomni/biomni/tool/tool_description/bioengineering.py`](https://github.com/snap-stanford/biomni/biomni/tool/tool_description/bioengineering.py)), genomics ([`/snap-stanford/biomni/biomni/tool/tool_description/genomics.py`](https://github.com/snap-stanford/biomni/biomni/tool/tool_description/genomics.py)), immunology ([`/snap-stanford/biomni/biomni/tool/tool_description/immunology.py`](https://github.com/snap-stanford/biomni/biomni/tool/tool_description/immunology.py)), and pharmacology ([`/snap-stanford/biomni/biomni/tool/tool_description/pharmacology.py`](https://github.com/snap-stanford/biomni/biomni/tool/tool_description/pharmacology.py)).

Each tool is described using a dictionary that specifies its purpose, a unique programmatic name, and detailed specifications for its input parameters. Parameters are categorized as either required or optional, with each entry defining its name, type (e.g., [`str`](https://github.com/snap-stanford/biomni/biomni/llm.py#L10), [`int`](https://github.com/snap-stanford/biomni/biomni/utils.py#L262), [`List[str]`](https://github.com/snap-stanford/biomni/biomni/utils.py#L550)), a human-readable description, and a default value if applicable. This standardized format enables automated systems to understand a tool's capabilities, dynamically generate user interfaces for input, and validate provided arguments before execution.

For instance, tools for biochemical analysis, such as [`analyze_circular_dichroism_spectra`](https://github.com/snap-stanford/biomni/biomni/tool/biochemistry.py#L1), define required inputs like [`sample_name`](https://github.com/snap-stanford/biomni/biomni/tool/genomics.py#L1483) and [`wavelength_data`](https://github.com/snap-stanford/biomni/biomni/tool/biochemistry.py#L4), alongside optional ones like [`temperature_data`](https://github.com/snap-stanford/biomni/biomni/tool/biochemistry.py#L6). Similarly, the [`annotate_celltype_scRNA`](https://github.com/snap-stanford/biomni/biomni/tool/genomics.py#L463) tool specifies various optional parameters for customization. This consistent metadata structure is crucial for the [`biomni`](https://github.com/snap-stanford/biomni/README.md#L25) agent's ability to orchestrate complex research tasks by dynamically selecting and executing the appropriate tools based on the problem at hand, as discussed further in [Dynamic Resource Management and Retrieval](#project-overview-and-core-components-dynamic-resource-management-and-retrieval).
