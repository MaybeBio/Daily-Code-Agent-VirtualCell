### ReAct Agent Implementation and State Management
The [`react`](https://github.com/snap-stanford/biomni/biomni/agent/react.py#L38) agent, implemented in [`/snap-stanford/biomni/biomni/agent/react.py`](https://github.com/snap-stanford/biomni/biomni/agent/react.py), employs the ReAct (Reasoning and Acting) pattern within the [`LangGraph`](https://github.com/snap-stanford/biomni/biomni/agent/react.py#L265) framework to address biomedical challenges. This design allows the agent to dynamically reason, execute tools, and observe results in an iterative cycle, forming a robust workflow for complex problem-solving.

Central to the agent's operation is its state management, handled by the [`AgentState`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L51) [`TypedDict`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L8). This structure primarily maintains a sequence of [`BaseMessage`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L12) objects, enabling the agent to track conversational history and internal thought processes. The [`add_messages`](https://github.com/snap-stanford/biomni/biomni/agent/react.py#L15) reducer within [`AgentState`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L51) ensures that the message sequence is consistently updated, reflecting the agent's evolving context.

The agent's ability to interact with its environment is facilitated by its dynamic tool management. During initialization, the [`react`](https://github.com/snap-stanford/biomni/biomni/agent/react.py#L38) agent loads available tools by reading API schemas from [`module2api`](https://github.com/snap-stanford/biomni/biomni/utils.py#L871) and converting them into [`LangChain`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L2196) compatible tools. A key design choice is the integration of a timeout mechanism for all tools via [`_add_timeout_to_tools`](https://github.com/snap-stanford/biomni/biomni/agent/react.py#L90). This function wraps tool executions in a separate process, preventing any single tool from indefinitely blocking the agent's progress and enhancing overall system reliability. New tools can be dynamically added using the [`add_tool`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L225) method, which automatically generates API schemas from Python functions and applies the necessary timeout wrappers.

The agent's workflow is constructed using [`LangGraph`](https://github.com/snap-stanford/biomni/biomni/agent/react.py#L265) within the [`_create_custom_react_agent`](https://github.com/snap-stanford/biomni/biomni/agent/react.py#L268) method. This workflow defines a cycle between calling the Language Model (LLM) and executing tools. The [`call_model`](https://github.com/snap-stanford/biomni/biomni/agent/react.py#L277) node invokes the LLM to determine the next action, while the [`tool_node`](https://github.com/snap-stanford/biomni/biomni/agent/react.py#L285) executes the tools suggested by the LLM. A conditional edge function, [`should_continue`](https://github.com/snap-stanford/biomni/biomni/agent/react.py#L310), governs the flow, allowing the agent to repeatedly reason and act until a final solution is reached. This [`StateGraph`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L15) setup provides a clear and manageable representation of the agent's decision-making process and execution path.

Furthermore, the [`react`](https://github.com/snap-stanford/biomni/biomni/agent/react.py#L38) agent incorporates dynamic resource retrieval to optimize its problem-solving capabilities. When enabled, the [`go`](https://github.com/snap-stanford/biomni/biomni/agent/a1.py#L1759) method utilizes a [`ToolRetriever`](https://github.com/snap-stanford/biomni/biomni/model/retriever.py#L8) to intelligently select the most relevant tools, data lake items, and libraries based on the user's input. This prompt-based retrieval mechanism ensures that the LLM's context is enriched with only pertinent information, reducing cognitive load and improving the efficiency and accuracy of its responses. This selective resource integration allows the agent to adapt its capabilities to the specific demands of each biomedical query.

The overall approach to dynamic resource management and retrieval is further detailed in [Dynamic Resource Management and Retrieval](#project-overview-and-core-components-dynamic-resource-management-and-retrieval).
